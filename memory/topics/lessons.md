# Lessons Learned

- Digest format: Markdown with clickable links, under 4000 chars. Always save files AND commit before logging.
- The fork's GH token carries **both `repo` and `workflow` scopes** (verified `gh auth status` 2026-09-14) — it CAN push `.github/workflows/` changes. The old "PAT lacks the workflows scope" lesson is stale.
- MEMORY.md row sprawl blocks every skill via the Read ~25K-token cap — `memory-flush` enforces per-row char caps; detail belongs in daily logs / `memory/topics/`.
- Cross-repo `gh repo clone` + push (e.g. `changelog` push-to branch): clone into `output/scratch/` (gitignored, inside the workspace), not `/tmp` (sandbox blocks paths outside the repo). Run `gh auth setup-git` before `git push`. `gh pr create` from that clone needs `--head <branch> --base <base>` explicitly. [source: logs/2026-10-12#changelog]
- `feature`/`repo-actions` can waste CI building duplicate PRs — open-PR dedup + `memory/topics/blocked-features.md` + `memory/topics/pre-existing-features.md` prevent re-suggesting shipped or blocked work.
- `feature` weighs a hyperstition-deadline tiebreaker: an unbuilt candidate matching an unresolved Active Target with a ≤10-day deadline wins over a higher-raw-impact evergreen.
- Skills consuming X.AI/Twitter data must have a prefetch case in `scripts/prefetch-xai.sh`; without it the skill runs with zero data. Fixed for `tweet-digest` via PR #67.
- Social Pulse `xai` flag: `xai=quiet` = prefetch ran but token quiet (< threshold); `xai=skip` = no data fetched (cache missing or key unset). PR #75.
- token-movers: during multi-day reporting gaps, compute 24h Δ from GT/DS native `h24` fields rather than the stale stored price (used 2026-08-04 after a 5-day gap).
- Shell `>` redirection is blocked by the Bash permission layer even for allowed-workspace paths (curl `-o` and the Write tool still work) — stage output under `output/scratch/` (gitignored). Found by `shiplog` 2026-08-18.
- Root-level `notify`/`notify-jsonrender`/`secretcurl` are generated copies of `scripts/*.sh`, regenerated by the run harness — expect them as untracked/modified in `git status` (harmless drift, not lost work). First traced 2026-08-24 after aeon-update's PR #146.
- Claude-subscription exhaustion (2026-08-31) triggers a harness pin to a GLM gateway (`GLM_API_KEY`/`ZAI_API_KEY`) — the pin itself returned empty zero-token responses intermittently. Wait for 2+ consecutive clean canary runs (token-movers + fetch-tweets) before calling an outage resolved.
- eyebrow gate (CI pins **v0.4.2**): `eyebrow.policy.json` has `allowContentDrift: true` / `failOnCapabilityExpansion: true` / `failOnSeverity: critical`, so `verify` fails ONLY on a **new egress host** or a **new CRITICAL**. Rule for aeon-update: a modified existing skill is safe to apply UNLESS its SKILL.md text introduces a new URL host (even an example one). A brand-NEW skill needs an `eyebrow scan` and the binary isn't in the sync env, so new skills get held.
- token-movers: the 14-session DexScreener-vs-GeckoTerminal liquidity divergence (09-16→09-29, ~$120-159K DS vs ~$278-350K GT) closed 09-30 — GT's pool reserve dropped 57% overnight ($320.6K→$137.9K) to within 0.07% of DS's $137.8K, no swap large enough to explain it (LP event or GT calc correction). DS's lower figure may have been closer to true reserve all along. Open operator decision: pick a canonical source or watch more sessions. Both sources have since agreed (~$125-135K through 10-18).
- Zero-token "completed" harness runs (terminal_reason=completed, total_cost_usd=0, no error) recurred 2026-09-22 (4 token-movers fails) and again 2026-10-06 (token-movers 3, fetch-tweets 4, heartbeat 2 — one systemic event). Both recovered on their own. `skill-repair` is disabled in `aeon.yml`, so health issues #182/#184/#195/#196 stay open until closed manually or skill-repair is re-enabled.
- token-movers: the mmETH/MiroShark pool ($2.6M reserve, created 2026-09-14) logged zero real trades through 2026-09-20 — treat as seeded/inactive liquidity; keep excluding it from volume/whale calcs until it shows activity.
- `aeon-update` cron-state entries can get stuck on `last_status: dispatched` for 100+ hours even though the run completed (lost outcome-write). First confirmed after the 2026-09-28 run (PR #183, issue #184). Before treating `dispatched` as a live stuck run, cross-check the PR-merge timestamp and any skill-health issue.
- The Bash permission layer false-positives "Contains expansion" on `${VAR}`/`${VAR:-default}` even for non-secret values — pre-resolve into plain `$VAR` or a literal. Found by `changelog` 2026-10-05.
- `rm -rf` is categorically blocked by the tool allowlist — use an exists-check substitute instead of an unconditional `rm -rf "$WORK_DIR"`. Found by `changelog` 2026-10-05.
